# レビュー収集 実行手順

`tools/collect_reviews.py` を動かすまでの手順。

前提として、**このスクリプトを書いた環境は Amazon・Goodreads・各APIのいずれにも
到達できなかった**。ロジック（絞り込み・分類・レポート生成）はテスト済みだが、
取得層とパーサは実物を見ずに書いてある。初回は必ず `--dump-raw` を付けること。

背景と、そもそも何件取れるのかは `Amazon和風レトロ塗り絵_調査メモ.md` を先に読む。

---

## 1. 環境のネットワークを開ける

[claude.ai/code](https://claude.ai/code) で、メッセージ入力欄のすぐ上にある雲アイコン
（現在の環境名が出ているボタン）を押す。設定ページや直リンクは無く、ここからしか開けない。

**Add cloud environment** で新規作成する。既存の Default を書き換えると
他の作業に影響するため、`review-research` のような別環境にする。

**Network access** を `Custom` にして、**Allowed domains** に1行ずつ:

```
amazon.com
*.amazon.com
goodreads.com
*.goodreads.com
api.scraperapi.com
api.rainforestapi.com
realtime.oxylabs.io
```

実際に使うAPIの行だけ残せばよい。商品画像も見るなら
`*.media-amazon.com` と `*.ssl-images-amazon.com` を足す。

**「Also include default list of common package managers」に必ずチェックを入れる。**
外すと上記以外が全て遮断され、pip も apt も動かなくなる。

保存したら、**新しいセッションを開始する**。編集は実行中のセッションには反映されない。
ブランチは `claude/amazon-retro-coloring-reviews-pndolx` を指定する。

## 2. APIキーを渡す

Goodreads は不要。Amazon 側だけ必要。

```bash
export REVIEW_API_KEY="..."          # ScraperAPI / Rainforest
export OXYLABS_AUTH="user:password"  # Oxylabs のみ
```

環境設定ダイアログの Environment variables 欄は、その環境を使う全員から読めるので
**APIキーを置かないこと**（ダイアログ自身も警告している）。セッション内で export する。

## 3. まず1商品で試す

```bash
python3 tools/collect_reviews.py --source amazon --provider scraperapi --dump-raw --limit 1
```

`--dump-raw` で生レスポンスが `data/raw/` に残る（`data/` は .gitignore 済み）。

ここで失敗するのが普通。順に潰す:

| 症状 | 見るところ |
|---|---|
| 401 / 403 | キー。プロバイダのURL・パラメータ名も未検証なので `fetch_amazon` を疑う |
| 200 だが 0 件 | `parse_amazon` のフィールド名。`data/raw/*.json` の実物と突き合わせる |
| KeyError / TypeError | 同上 |

直すのは `fetch_*` と `parse_*` の中だけで済むように分離してある。

## 4. Goodreads のパーサ（実装済み・2026-08-05）

`parse_goodreads` は実物のHTMLを見て実装済み。以下は調査結果の記録。

### 本文の在り処

**`application/ld+json` は外れ。** `@type: Book` が1つあるだけで、中身は
name / isbn / author / aggregateRating（平均と総数）まで。schema.org の
`review` プロパティは無く、レビュー本文は1文字も入っていない。

**当たりは `__NEXT_DATA__`**（Next.js のSSRペイロード）。
その中の Apollo キャッシュにレビュー本体が正規化された形で入っている:

```
props.pageProps.apolloState
  ├ "ROOT_QUERY"
  │    └ "getReviews" -> {totalCount, edges:[{node:{__ref:"Review:..."}}]}
  └ "Review:kca://review:goodreads/..."
       rating        1〜5 の int（未評価は null）
       text          本文。プレーンテキストではなく HTML 断片
       createdAt     エポックミリ秒
       spoilerStatus bool
       creator       {"__ref": "User:..."}
```

確認は次で足りる:

```bash
python3 -c "import re,json,sys;h=open(sys.argv[1],encoding='utf-8').read();\
d=json.loads(re.search(r'<script id=\"__NEXT_DATA__\" type=\"application/json\">(.*?)</script>',h,re.S).group(1));\
a=d['props']['pageProps']['apolloState'];\
print(sum(1 for k in a if k.startswith('Review:')),'件')" data/raw/goodreads_<isbn>.html
```

注意点:

- **1商品30件が上限。** `edges` は初期表示分だけで、続きはクライアント側の
  GraphQL 追加リクエスト。HTMLからは取れない。
- **`text` は HTML 断片。** `<br />` `<b>` `<i>` `<a>` `<blockquote>` `<img>` と
  HTMLエンティティを含む。`_html_to_text` で素のテキストに落としてから
  `review_filter` に渡している。`<br />` は改行にする（改行も文の区切りとして
  使われるため）。
- **表題は無い。** Goodreads のレビューに Amazon のような見出しは無いので
  `review_title` は常に None。
- **レビュー0件だと `getReviews` キー自体が生えない。** 異常ではないので
  空リストを返す。`__NEXT_DATA__` ごと無い場合だけ ValueError にしている。
- **`product_id` には ISBN ではなく ASIN を入れている。** レポートは商品単位で
  集計するため、Amazon 側と同じキーにしないと同じ商品が2つ並ぶ。
  出所は `source` で区別する。

Goodreads の公式APIは2020年12月に廃止済みなのでHTMLを読むしかない。
なお 979-8 始まり（KDP発行）の収録は歯抜けで、404 や空応答は普通に起きる。

### 実行結果：**Goodreads 側にレビューは1件も無い**

15商品すべてでページ自体は存在したが、`Work.stats` は全商品で
`ratingsCount = 0` / `textReviewsCount = 0` だった。

```
python3 tools/collect_reviews.py --source goodreads --dump-raw
-> 取得 0 件
```

パーサの不具合ではなく、**この商品群が Goodreads で誰にも評価されていない**。
KDP発行の塗り絵は Goodreads にほぼ読者が付かないため、想定内ではある。
つまり実データは Amazon 側（§3）から取るしかない。Goodreads は当面
「動くが収穫ゼロの経路」として置いておく。定期的に再実行して増えたか見る用途。

## 5. 全件回してレポートを組む

```bash
python3 tools/collect_reviews.py --source amazon --provider scraperapi
python3 tools/collect_reviews.py --source goodreads
python3 tools/collect_reviews.py --report
```

`docs/レビュー分析.md` が生成される。商品別の星5・星1と、
星1で多い不満（AI生成疑い・使い回し・画質不良など）の集計が出る。

## 絞り込みロジック

`tools/review_filter.py`。ネットワーク不要なので単体で試せる。

```bash
cd tools && python3 test_review_filter.py
```

判定は**文単位**。レビュー1件を丸ごと残す／捨てるのではなく、
中身に言及している文だけを抜く。「紙が薄い。でも線は綺麗」が混在するのが
普通のため、前半を捨てて後半だけ残す。

- **一次語**（`PRIMARY`）: illustration / line art / detail / composition など、
  絵そのもの・線・密度に関する語。これが出た文だけ残る。
- **物理語**（`PHYSICAL`）: paper / bleed / binding / shipping / price など。
  これ「だけ」の文は落ちる。一次語と同居する文は残し、印を付ける。
- **地雷語**（`RED_FLAGS`）: AI生成疑い・トレース・使い回し・画質不良・
  線が塗れない・題材が的外れ。星1の分析用に別集計する。

題材語（japanese, showa, retro など）は**一次語に入れていない**。
このジャンルではほぼ全レビューに出るので、入れると絞り込みが効かなくなる。

チューニングは `PRIMARY` / `PHYSICAL` / `RED_FLAGS` のリストを編集し、
テストを足してから回す。

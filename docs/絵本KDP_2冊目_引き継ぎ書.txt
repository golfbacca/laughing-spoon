  読む順番

    2. docs/絵本KDP_調査と設計_作業指示書.txt の 0章（罠）と 7章（キャラ設計）
       ※全2700行あるので、頭から通読しなくてよい。必要な章を拾う。
    3. docs/絵本KDP_KDP登録用_内容紹介とキーワード.txt（登録画面の答え一式）

  最初に実行すること
    Amazonに200が返るか確認する。ここが通らないと調査が何もできない。

      curl -sS -m 40 --compressed \
        -H 'User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/125.0 Safari/537.36' \
        -H 'Accept-Language: ja-JP,ja;q=0.9' \
        -b 'i18n-prefs=JPY; lc-acbjp=ja_JP' \
        'https://www.amazon.co.jp/dp/B0CXTM195D' -o /tmp/t.html ; wc -c /tmp/t.html

    通ったかどうかの見分け方（バイト数だけで判断しない）

        grep -c productTitle /tmp/t.html        商品ページ → 1以上なら通った
        grep -c 's-search-result' /tmp/s.html   検索ページ → 1以上なら通った

      1MB前後が返れば通っている。
      2〜4KB で <title>Amazon.co.jp・本文に Captcha / automated access が
      入っていれば、ボット判定で弾かれている（2026-08-24 に実際に食らった）。

    弾かれたときの対処
      ・数分待つ。90秒では戻らなかった。10分以上あけるつもりで。
      ・リクエストの間隔を4〜5秒あける。連続で叩かない。
      ・1セッションで20回も叩けば止まる。取ったHTMLはファイルに保存し、
        解析はローカルでやり直す。同じページを取り直さない。
      ・--compressed を忘れるとgzipのまま落ちてきて読めない（実際にやった）。

0-B. キャラを崩さないために（ここだけは飛ばさないこと）
----------------------------------------------------------------

  セッションが変わってもキャラは崩れない。設計は文章と絵に残してあり、
  記憶に頼っていない。崩れるとしたら理由はただ一つ、
  「参照画像を渡さずに、文章の指定だけで生成したとき」である。
  1冊目で実際にそれをやって、ミオの目もトトンの耳も別物になった。

  必ず守ること

    絵を1枚でも作る前に、この2つを開く
      docs/絵本KDP_画像/参照/キャラクター基準シート.jpg
        トトン全身・ミオ全身・2人の大きさの比・両者の顔の
        5面をまとめた基準シート（承認済みの最終画から作った）
      docs/絵本KDP_組版/gen_image.py
        参照画像の渡し方とKEEP文を固定した生成スクリプト

    生成は必ず gen_image.py を通す。curlを手で書き直さない。

      新しい構図をゼロから作るとき
          generate(prompt, "out.jpg", ref_images=[REF_SHEET])

      既存ページを手直しするとき（こちらのほうが崩れにくい）
          generate(prompt, "out.jpg", ref_images=[直すページ, REF_SHEET])
          → 「この絵のキャラは確定済み。描き直すな」
            「変えるのは次の◯点だけ」と列挙する

    KEEP文（gen_image.py に埋め込み済み）は毎回入る。消さない。

  なぜ文章だけでは足りないか

    CHARACTER LOCK は7章に英語で細かく書いてあるが、
    構図の指示（顔の向き・表情・動き）が強いと、モデルはそちらに
    引きずられて造形のほうを作り直してしまう。
    文章は「言葉にした属性」しか縛れない。
    言葉にしていない属性（目の大きさ、耳の付け根の位置、頭身）は
    毎回ぶれる。絵を見せるのが唯一の確実な縛りである。

  確認のしかた

    ・新しい絵ができたら、基準シートと並べて見る。
      特に トトンの耳の位置と大きさ ／ ミオの目 ／ 2人の身長比。
    ・身長比は目で見ずに測ってもよい（1冊目でやった）。
      色で切り分けて高さを比べる。トトンはミオの55%前後。

5. 踏んではいけない罠（全部一度踏んだもの）
----------------------------------------------------------------

  【調べる】
    ・curl に --compressed を付けない → gzipのまま落ちて読めない
    ・JPYクッキーを付けない → 価格がUSD表示になる
    ・Amazonを連続で叩く → Captchaページ（2〜4KB）が返り、数分は戻らない。
      4〜5秒あける。1セッションの総数も抑える。取ったHTMLは保存して使い回す

  【描く】
    ・「描くな」だけでは足りない。必ず「代わりにこれを描け」を添える
    ・CHARACTER LOCK に書いていない属性は必ずぶれる
    ・上部に余白を描かせようとすると幽霊の頭が湧く。余白は組版側で作る
    ・プロンプトを機械的に分割すると、区切り線が本文に残って
      ほぼ空のプロンプトで生成される。promptTokenCount で気づける
    ・キャラが崩れたら「作り直す」のではなく「承認済みの絵を編集する」
    ・直線・矩形・タイル・下端の切り方など幾何の細部は、
      3回直らなければ4回目を生成に賭けない。画素を直接いじるほうが速い

  【組む】
    ・固定レイアウトEPUBは全ページ同寸でないと引き伸ばされる。
      build_epub.py に検査を入れてあるので、寸法が違えば止まる
    ・本の中に表紙ページを持たせない。KDPが1ページ目に差し込むので重複する
    ・ストア表紙を1:1.6にすると、正方形の本では1ページ目が縮む
    ・代替テキストを空にしない。焼き込んだ本文は読み上げに届かない
    ・左右対称であるべき背景は、片側だけ生成が省略されることがある。
      原寸で左右を並べて見るまで気づけない

  【出す】
    ・Geminiのクレジットは、課金したGoogleアカウントとAPIキーの
      プロジェクトが一致していないと増えない。
      AI Studio の URL の /u/0/ /u/1/ でアカウントを見分ける
    ・DRMは出版後に変更できない
    ・KDPセレクトは90日ごとに自動更新される

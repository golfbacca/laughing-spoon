----------------------------------------------------------------

STEP1 棚の調査      : 中断（Amazonへの直接アクセスが遮断されたため）
STEP2 逆質問        : 未着手

■ 中断の理由と対処（2026-08-17）

cloud環境のネットワークポリシーが Trusted のため、amazon.co.jp が
egress proxy に 403 で拒否された。実測ログ:

    curl https://www.amazon.co.jp/
      → CONNECT tunnel failed, response 403

これはTLSやプロキシ設定の不具合ではなく、環境のポリシー拒否である。
セッション内部からは解除できない。

対処: claude.ai/code のメッセージ入力欄の上のクラウドアイコン
      → 対象環境にホバー → 歯車アイコン
      → Network access を Custom に変更
      → Allowed domains に以下を1行ずつ記入

          amazon.co.jp
          *.amazon.co.jp
          note.com
          *.impress.co.jp

      → 「Also include default list of common package managers」に
        必ずチェックを入れる（外すとnpm等の既定許可が消える）

注意1: 環境設定はセッション起動時に読まれるため、変更後は
       新しいセッションを立てる必要がある。実行中のセッションには効かない。
注意2: 許可しても取得できる保証はない。Amazonはデータセンター由来の
       自動アクセスにCAPTCHA・503を返すことが多く、/gp/bestsellers の
       ような動的ランキングページは特に返さない可能性が高い。
       空振りした場合は「利用者が画面の数字を貼る」方式に切り替える。

1. 絶対に守る前提（毎回これを守ること）
----------------------------------------------------------------

- 証拠主義。「人気らしい」「ウケそう」は禁止。
  順位・レビュー数・出版形態（電子/ペーパーバック）・シリーズの有無など、
  確認できた事実だけを数える。
  確認できなかったものは「根拠未取得」と明記する。推測を事実として書かない。

- 売れている型から外れた「いい話」を設計しない。
  絵本は「親の困りごとに効く道具」として買われている前提で設計する。

- 既存の絵本・キャラクター・作家の画風の模倣は絶対にしない。
  （著作権侵害・出版停止リスク）型を借りて、中身は完全オリジナル。

- KDPのAI生成コンテンツ申告を毎回リマインドする。隠すのは規約違反。

- 出版形態はペーパーバック＋電子の両方を基本とする。

- 価格帯の上限額・配信コスト・印刷費・振込日数といった
  「その時々で変わる数字」を、記憶から断定してはいけない。
  必ず「KDPの価格設定画面の実額で確認してください」と指示する形にする。
  概算を出す場合は「概算」と明記する。


----------------------------------------------------------------
2. 進め方（STEP1〜STEP5）
----------------------------------------------------------------

■ STEP1 棚の調査（証拠主義）

web検索で、Amazonの絵本・児童書ランキングと、KDP個人出版絵本で
実際に売れている形跡のあるものを調査する。

1-a. 売れている絵本に共通する型を、事実ベースで4つ以内に絞る。
     各型に、確認できた根拠（順位・レビュー数・出版形態）を必ず添える。

1-b. あわせて「親がAmazonの検索窓に実際に打っている言葉」を、
     サジェストや売れ筋タイトルから3つ拾って提示する。
     ※この3語は、利用者が自分でAmazonの検索窓に打って目で確認する前提。
       「確認してください」と一言添える。

1-c. 個人出版とわかる絵本を3冊選び、価格とレビュー数を並べる。
     そのうえで「レビューを書くのは買った人の一部（仮に1%とする）」
     という推定を明示したうえで、販売冊数と生んだ金額を逆算する。
     使った仮定は必ず「推定」とラベルを付け、
     実際の販売数ではないことを明記する。

■ STEP2 逆質問

利用者に2つ質問する:
  1. あなたが親・祖父母・身近な子との関わりで、
     一番困った（困っている）ことは何ですか
  2. 対象にしたい年齢はいくつ頃ですか（不明なら悩みから提案）

■ STEP3 1冊の設計図

STEP1の型 × STEP2の悩み で設計する。
  - タイトル案（対象年齢を明記する型。3案）
  - 主人公キャラ（1体。見た目を言語で完全固定:
    種類/色/服/持ち物/表情の癖）
  - 構成（全16ページ・見開き8場面の場面割り。悩み→共感→解決の流れ）
  - シリーズ展開案（同じキャラで次に出す悩み3つ）
  - この1冊がSTEP1の型4つのどれに乗っているかの対応表
    （どれにも乗っていない要素があれば、その場で指摘する）

■ STEP4 キャラ固定の一括画像指示文（Gemini用・英語）

  - キャラの固定記述を全場面の指示に埋め込む（ブレ防止）
  - 8場面＋表紙の一括指示（場面ごとの構図・感情）
  - 絵本向けタッチ指定（やわらかい・明るい・文字スペース確保）
  - 印刷を見据えた高解像度指定

  ※1枚ずつ小出しにする形式にはしない。顔がぶれて工数が跳ね上がるため、
    必ず全場面を一括で出せる形にまとめること。

■ STEP5 KDP出版文

  - タイトル（日英）・サブタイトル
  - 内容紹介文（親の検索意図に合わせた書き出し）
  - カテゴリ推奨
  - キーワード7個
    ※うち3つは STEP1-b で拾った「親が実際に打っている言葉」を必ず入れる。
      自分で考えた言い回しで埋めない。採用した語に【】を付けて示す。
  - 価格の考え方:
    電子は70%ロイヤリティが取れる価格帯を基本
    （日本の読者向け70%はKDPセレクト登録＝90日Amazon独占が条件）。
    ペーパーバックは60%－印刷費の構造を説明したうえで推奨価格。
    ※70%帯の上限額・配信コスト・印刷費は変更されることがあるため、
      金額を断定せず「価格設定画面の実額を見て確定してください」と指示する。
  - AI申告のリマインド

4. 再開時にやること（優先順）
----------------------------------------------------------------

1. Amazonにアクセスできるか実測する
       curl -sS -o /dev/null -w "%{http_code}\n" https://www.amazon.co.jp/
   403 が返るなら、まだポリシーが効いていない。上記2の設定を見直す。

2. アクセスできた場合:
   - 絵本・児童書 売れ筋ランキング   /gp/bestsellers/books/466306
   - 絵本 Kindle 売れ筋ランキング     /gp/bestsellers/digital-text/2293383051
   - 絵本 新着ランキング              /gp/new-releases/digital-text/2293383051
   上位20件の 順位・書名・出版形態・価格・星・レビュー数 を取得し、
   3章の「根拠未取得」を実測値で埋める。

3. アクセスできない場合（CAPTCHA・503含む）:
   利用者に画面の数字を貼ってもらう方式に切り替える。
   貼ってもらう項目は
   「タイトル・順位・価格・出版形態・星・レビュー件数」の6つ。

4. STEP1-a を4つ以内に確定 → 1-b → 1-c の逆算 → STEP2の逆質問へ。

■ STEP1-c の逆算式（そのまま使う）

   推定販売冊数 = レビュー数 ÷ 0.01
   推定売上     = 推定販売冊数 × 販売価格 × ロイヤリティ率
                  （電子70% ／ ペーパーバックは60%－印刷費）

   ※「レビューを書くのは買った人の1%」は一般に言われる仮定であって、
     Amazonが公表した数値ではない。実際は0.1%〜数%まで幅がある。
     出力時は必ず「推定」とラベルを付け、
     実際の販売数ではないことを明記する。
